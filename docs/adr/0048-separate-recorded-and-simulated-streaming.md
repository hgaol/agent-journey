# Separate recorded and simulated streaming in Replay

The Terminal Replay Debugger offers event steps, Recorded Streaming, and opt-in Simulated Streaming. Recorded Streaming is available only when Source Evidence yielded Delivery Trace chunks and preserves their order/timing; Simulated Streaming reveals agent output and reasoning in deterministic sixteen-character chunks—four times the original prototype rate—but labels every such frame `SIMULATED` and never upgrades the Fidelity Manifest. A separate user-selected Streaming Speed multiplier controls only transitions within one recorded or simulated content stream, while Timeline Speed continues to control intervals between Activities. Browser playback uses deadline-based scheduling, so rendering latency is subtracted from the next delay and overdue frames may be skipped to preserve the selected wall-clock cadence. After the first chunk of one Activity, the iframe updates only that Activity instead of rebuilding and retransmitting the complete Stage. Remaining duration uses a precomputed suffix schedule, and the visual timeline renders at most one marker per Activity, with bounded density, rather than one DOM control per content chunk. This keeps one Streaming Speed consistent across small and very large Journeys while providing TUI-like motion without presenting invented token cadence as forensic evidence.
