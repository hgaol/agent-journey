# Use a causal Activity Graph as the canonical model

Canonical Activity forms an ordered graph rather than a flat transcript. Stable Activities retain source order and optional source-supported time while explicit relationships represent turns, tool calls and results, nested threads, forks, and replacement; transcript and timeline layouts are derived views. Turns and transcript layouts remain derived, provenance-aware groupings rather than core Activities. Incremental source chunks and repeated snapshots form optional Delivery Traces on semantic Activities instead of polluting the graph with transport fragments. This is more complex than a message list, but it preserves causality and parallel work without inventing chronology or interaction boundaries when sources provide incomplete evidence.
